# AutoSGuitar

Sforzando 音源 **Standard Guitar** 向けに、MIDI へキースイッチとコントロールチェンジを
ルールベースで自動付加するツール。

DAW で手打ちする際の**雛形（叩き台）**を生成することを目的としています。
完全自動での完成品生成は目指さず、ツールが大部分を埋め、残りを
**注釈レイヤー**経由で指示して往復する運用を想定しています。

> Phase 1 実装済み。設計と根拠はすべて [docs/](docs/) にあります。

## インストール

```console
python -m venv .venv
.venv\Scripts\pip install -e .
```

依存は `mido` と `PyYAML` のみです。

## 使い方

```console
autosguitar in.mid -o out.mid --report decisions.csv
```

出力は type-1 MIDI で、生成されたキースイッチは専用トラック **`AutoSG_KS`** に
分離されます。入力トラックは一切書き換えません。

```
out.mid
 ├─ [Guitar]     ← 入力のまま（注釈ノートも保持）
 └─ [AutoSG_KS]  ← 生成された KS / CC（再実行のたびに作り直す）
```

DAW 側では両トラックを同じインストゥルメントに送ってください。
単一トラックにまとめたい場合は `--inline` を使います。

### 主なオプション

| オプション | 内容 |
|---|---|
| `-o, --output FILE` | 出力 MIDI（既定: `<入力>_ks.mid`） |
| `--rules rules.yaml` | ルール設定。変えたい項目だけ書けば既定にマージされる |
| `--report FILE.csv` | 判定レポート。**どの音がなぜその奏法になったか**が全部載る |
| `--inline` | KS を実音トラックにマージして単一トラックにする |
| `--export` | 注釈ノート（105–127）を除去する |
| `--track N` | 処理対象トラック（既定: 実音を最も多く含むトラック） |
| `--dry-run` | MIDI を書かずレポートのみ |

全オプションは [docs/05-architecture.md §5.5](docs/05-architecture.md)。

## 注釈レイヤー

自動判定できないもの（ハーモニクス、チョーキング、リード/バッキングの別）は、
**ピアノロールに MIDI 105–127 のノートを描いて**指示します。

- **ノートの音程** = 指示の種類
- **ノートの長さ** = 適用範囲

長い音符なら区間指定、実音 1 個に重ねる短い音符ならピンポイント指定になります。

> **Studio One 上では A6–G8 と表示されます。**
> Studio One はヤマハ式（C-2=0）、音源のマニュアルは C-1=0 表記のため、
> ノート名が 1 オクターブずれます。詳細は
> [docs/02-sound-source-spec.md §2.1](docs/02-sound-source-spec.md)。

主な指示（全一覧は [docs/03-annotation-layer.md](docs/03-annotation-layer.md)）:

| ノート | 意味 |
|---|---|
| 106 | パームミュートを強制 |
| 109 / 110 | ナチュラル / ピッキングハーモニクス |
| 116–118 | チョーキング 半音 / 1音 / 1音半 |
| 120–123 | context: バッキングリフ / コード / リード / クリーン |
| 125 / 126 | ダウン / アップを強制 |
| 127 | ロック（この区間には何も生成しない） |

### 往復ワークフロー

1. 実行して雛形を得る
2. DAW で鳴らし、直したい箇所を見つける
3. **キースイッチではなく、元トラックに注釈ノートを描く**
4. 再実行する

`AutoSG_KS` トラックは毎回まるごと作り直されるため、何度実行しても
結果は同じになります（冪等）。手で置いたキースイッチはツールが尊重し、
重複して生成しません。

## 自動判定の範囲（Phase 1）

| ルール | 内容 |
|---|---|
| ピッキング方向 | 拍位置からダウン / アップを決定。休符明けリセット、ギャロップ、低音リフのダウンピッキングに対応 |
| パームミュート | 音域・音価・**ペダルトーン検出**・和音構成の複合スコア |
| デッドノート | 極端に短く velocity の低い音 → フレットミュート / ブラッシング |
| レガート | 重なった近接音 → ハンマリング / プリング |

判定根拠はすべて `--report` の `source` 列に出ます
（`rule:palm_mute(pedal_tone)` / `annotation:110` / `manual_ks:21` など）。

スライド・チョーキング・ハーモニクスは Phase 1 では**注釈による指定のみ**対応です。
自動判定は Phase 2。

## 開発

```console
.venv\Scripts\pip install -e ".[dev]"
.venv\Scripts\python -m pytest
```

Sforzando は VST のみで CLI を持たないため音の自動テストはできません。
出力 MIDI をパースし直す構造テストを主軸にしています
（[docs/05-architecture.md §5.8](docs/05-architecture.md)）。
