# 04. キースイッチ付加ルール

各ルールの根拠を以下で示す。

- **［確］** — メーカー製サンプル MIDI / sfz / マニュアルで裏取り済み
- **［知］** — ギター奏法として一般に成り立つ経験則。実データによる裏取りはない

閾値はすべて `rules.yaml` で調整可能とする（§05-5.4）。ここに書く数値は初期値。

---

## 4.1 ピッキング方向（Down / Up）— 自動化の最大の価値

人間が手打ちすると最も面倒で、かつ機械が最も正確にできる部分。

### 基本ルール

1. 小節ごとに発音位置ヒストグラムから**支配的な分割**（8分 / 16分 / 3連）を推定
2. 各イベントを最寄りのグリッドスロットにスナップ
3. 偶数スロット → **Down**、奇数スロット → **Up**［知］

### 上書きルール（優先度順）

| # | 条件 | 挙動 | 根拠 |
|---|---|---|---|
| 1 | 直前に **1 拍以上の空白** | 次の音は必ず **Down** | ［知］休符明けは必ずダウンから入る。これを入れないと機械的で不自然になる |
| 2 | context = `backing_riff` かつ 低音域かつ PM 判定かつ **8分音符 ≦ 170 BPM** | **全部 Down** | ［知］メタルのバッキングはここが決定的。オルタネイトにすると腰が抜けた音になる。170 BPM 超は物理的に困難なのでオルタネイトへ |
| 3 | ギャロップ `8分 + 16分 + 16分` | **D, D, U** | ［知］ |
| 4 | 逆ギャロップ `16分 + 16分 + 8分` | **D, U, D** | ［知］ |
| 5 | 和音イベント | 強拍 → **Down**、弱拍 → **Up** | ［知］ |
| 6 | シンコペーション（食い。次の強拍を先取りする音） | **Up** | ［知］ |

### 出力

判定結果は **Down / Up の明示 KS** として出力する。

| 奏法 | Down | Up | （Alt は使わない） |
|---|---|---|---|
| サステイン | 24 | 25 | ~~26~~ |
| パームミュート | 27 | 28 | ~~29~~ |

**オルタネイト KS（26 / 29）を使わない理由:** ラウンドロビンが自動復帰しないため、
「ダウンで始まりアップで終わる」構成を保証しないとノリが崩れる［確・§02-2.9］。
Down/Up を明示すればこの制約から完全に解放され、しかも手打ちより確実に正確になる。

### アンチマシンガン

同音・同 velocity の連打は不自然に聞こえる。メーカー自身が `Anti_Machingun.mid` を
サンプルとして用意しているほど重要［確］。D/U の交替に加え、`--polish 2` で
velocity に揺らぎを与える。

---

## 4.2 パームミュート判定

単一条件では決まらないため、**複合スコア**で判定する。

| 特徴 | 条件 | 寄与 | 根拠 |
|---|---|---|---|
| 音域 | MIDI ≦ 57 | 強く支持 | ［知］低音弦の奏法。62 以上ではほぼ使わない |
| 音域 | MIDI ≧ 62 | 強く否定 | ［知］ |
| 音価比 | `duration / IOI ≦ 0.5` | 支持 | ［知］スタッカート気味に切るのが PM |
| **ペダルトーン** | §下記 | **最も強く支持** | ［確＋知］ |
| パワーコード | 2 音・音程差 7 または 12・ルート ≦ 57 | 支持 | ［知］ |
| 完全な和音 | 3 音以上の異なるピッチクラス | 否定 | ［知］フルコードは PM しない |
| 同音連打 | 直前と同じ音高 | 支持 | ［知］ |

### ペダルトーン検出（最も効く）

1〜2 小節窓の中で、以下をすべて満たす音高 `p` を**ペダル音**とみなし、
`p` の発音を**パームミュート**と判定する。

- `p` がその窓の**最低音**である
- `p` が **3 回以上**出現する
- `p` が窓内の全発音の **40% 以上**を占める

**裏取り:** デモの trk3 は **B1 (35) をペダルにして `Mute_Alt` / `Sus_Alt` を
交互に打つ**構造そのものであり、実データと一致する［確］。
これはメタル/ロックのリフで最も頻出する形であり、この 1 ルールで
バッキングの大半をカバーできる。

### 出力

`mute_down` (27) / `mute_up` (28)。ミュートの長さは **CC22** で調整（既定 127 = 最長）。
リフの粒立ちを出したい場合は CC22 を下げる（`rules.yaml` の `defaults.cc22`）。

## 4.3 デッドノート / ブラッシング

いわゆる「チャッ」という percussive なゴーストノート。

| 条件 | 出力 | 根拠 |
|---|---|---|
| 音価が極端に短い（≲ 16分の半分）**かつ** velocity ≦ 50 **かつ** 単音 | `mute_fret` (23) | ［知］ |
| 同上 **かつ** 和音 | `brush` (22) | ［知］ |

典型的には**和音の合間の 16 分裏**に入る［知］。グリッド上の位置も補助条件に使える。

---

## 4.4 ハンマリング / プリング（KS 30）

音源側に自動検出があるため、**KS 30 を置くだけでよい**［確］。
ツールがやるのは「ここはレガートである」という判定のみ。

### 判定条件（すべて満たす）

- 単声で連続している（和音ではない）
- **重なりがある**、または**間隔 ≦ `tpq/32`**
- **音程差 ≦ 5 半音**（同一弦で届く範囲）［知］
  - Phase 2 でフレットボードモデルを入れたら「**同一弦か**」という本来の条件に置換する（§4.8）

### 除外条件

| 条件 | 理由 |
|---|---|
| 休符明けの最初の音 | ［知］必ずピッキングされる。レガートにはならない |
| 直前がパームミュート | ［知］PM 中はレガートしない |
| 連続レガート句の**先頭音** | ［知］3 音以上のレガート句では、先頭だけピッキングし以降がレガート |

---

## 4.5 スライド（KS 31 / 32 / 33 / 34 + CC26 / CC27）

### レガートとスライドの切り分け［知］

| 条件 | 判定 |
|---|---|
| 重なり / 隣接、音程差 **≦ 5** 半音 | ハンマリング/プリング（§4.4） |
| 重なり / 隣接、音程差 **5〜12** 半音、**かつ前の音がある程度長い**（≧ 1/4 拍） | **スライド** |

短い 16 分音符へのスライドは物理的に不自然なので、音価の下限を設ける［知］。

### 出力

| 方向 | KS | 距離 CC |
|---|---|---|
| 上行 | `slide_up` (32) | CC26 |
| 下行 | `slide_down` (31) | CC26 |
| スライドイン | `slide_in` (33) | CC27 |

距離 → CC 値の変換は §02-2.6 のテーブルを使う（半音=8, 1音=24, 1音半=40,
2音=56, 2音半=72, 3音=88, 3音半=112）。CC は KS と同じ先行オフセットに載せる。

### スライドアウト（KS 34）

- **リリース側に配置する**（他の KS と規則が異なる）［確・§02-2.7］
- ただし **CC24 を 80–127 にすれば音源が自動でやる**［確・§02-2.5］

→ **フレーズ末を個別に打つ必要はない。CC24 で一括処理するのを既定とする。**
明示的に打ちたい場合のみ注釈 115 で指定する。

### スライドイン（KS 33）

句頭の長い音への「しゃくり」。**様式的な選択であり自動判定に馴染まない**ため、
Phase 1 では注釈 114 のみで対応する。

## 4.6 チョーキング（KS 91 / 92 / 93）

素の MIDI からは原則判定不能。ただし**機械的に取れるパターンが 2 つある**［知］。

### ① 書き下されたベンドの畳み込み

```
短い装飾音 A（≲ 1/8 拍）→ 重なり付きで直後に、A + 1〜3 半音 の長い音 B
    ↓
A を削除し、B に KS を付与
```

| 音程差 | KS |
|---|---|
| 1 半音 | `bend_ht` (91) |
| 2 半音 | `bend_wt` (92) |
| 3 半音 | `bend_1ht` (93) |

半音 / 1音 / 1音半 に直接対応する。**これは入力の音符を書き換える唯一のルール**なので、
既定で有効にするか要検討（`rules.yaml` の `bend.fold_grace_notes`、初期値 `true`）。
削除した装飾音は判定レポートに必ず記録する。

### ② ピッチベンドデータからの変換

入力にピッチベンドがある場合、深さから KS に変換する。

### 音域ゲート

いずれも **MIDI ≧ 55 前後**でのみ適用する。低音弦のチョーキングは実際には稀［知］。
Phase 2 でフレットボードモデルが入れば「高音弦かつフレット 5 以上」という
本来の条件に置換できる（1〜2 フレットでは物理的に曲げにくい）。

---

## 4.7 ハーモニクス

**自動判定は行わない。** 無理に推定すると誤爆が目立ち、ユーザーの信頼を失う。
注釈 109（ナチュラル）/ 110（ピッキング）のみで対応する。

---

## 4.8 フレットボードモデル（Phase 2 / 最大の品質レバー）

### 根拠

この音源の発音域は**7 弦 22 フレットのギターそのもの**である［確］。

```
最低音 B1 (35) = 7 弦開放
最高音 D6 (86) = 1 弦 E4(64) + 22 フレット   ← sfz の hikey=d6 と完全一致
```

開放弦（7 弦標準チューニング）:

| 弦 | 音名 | MIDI |
|---|---|---|
| 7 | B1 | 35 |
| 6 | E2 | 40 |
| 5 | A2 | 45 |
| 4 | D3 | 50 |
| 3 | G3 | 55 |
| 2 | B3 | 59 |
| 1 | E4 | 64 |

### 実装

音符列に対する動的計画法で運指コストを最小化する（タブ譜生成として確立した手法）。
コスト関数はフレット移動距離、フレット幅、開放弦の使用、弦移動などの重み付き和。

### 効果

| 用途 | 内容 |
|---|---|
| **和音の演奏可能性チェック** | 「同一弦に 2 音」「フレット幅が手を超える」を検出・警告。ラフ MIDI で最も起きがちで、**打ち込みがキーボード臭くなる最大の原因** |
| レガート / スライド判定 | 「音程差 ≦ 5」という近似を「**同一弦か**」という本来の条件に置換 |
| パームミュート判定 | 「低音域」を「**低音弦に割り当てられたか**」に置換 |
| チョーキング判定 | 「高音弦かつフレット 5 以上」 |
| ポジション移動検出 | フレットノイズの挿入位置が決まる。音源に **CC24 = 64–79「Position Change」** という専用リリーススタイルが用意されている［確］ |

### Phase 1 での準備

フレットボードモデル自体は Phase 2 だが、**Phase 1 のルールを
「弦割り当てが渡ってきたら差し替えられる」インターフェース**にしておく。

具体的には、音域による近似判定（§4.2 の「MIDI ≦ 57」、§4.4 の「音程差 ≦ 5」、
§4.6 の「MIDI ≧ 55」）を独立した述語関数として切り出し、
Phase 2 で実装を差し替えられるようにする。
