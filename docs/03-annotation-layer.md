# 03. 注釈レイヤー仕様

## 3.1 設計方針

自動ルールだけでは決まらないもの（ハーモニクス、チョーキング、スライドの意図、
リード/バッキングの別）をユーザーが指示するためのレイヤー。

要件:

1. **MIDI ファイル内で完結する** — サイドカーファイルは往復ワークフローを壊す
2. **Studio One で編集できる** — ノート単位の MIDI チャンネル編集は Studio One では不可
3. **注釈対象の実音と同じ画面で見える** — 分離トラックだと視認性が落ちる
4. **再実行しても消えない**

## 3.2 方式：発音域外ノートによる注釈

> **同一トラックのピアノロールに MIDI 105–127 のノートを描く。それが注釈。**

- **ノートの音程** = 注釈の種類
- **ノートの長さ** = 適用範囲。`[start, end)` に**発音開始**が入る実音すべてに適用

長い音符を描けば区間注釈、実音 1 個に重ねる短い音符を描けばピンポイント注釈になる。
**規則が 1 本で済み**、ピアノロールで線を引くだけで操作が完結する。

MIDI 105–127 が KSOP パッチで完全に未使用であることは sfz で確認済み（§02-2.2）。

> Studio One 上では **A6–G8** と表示される（§02-2.1 の表記系のずれに注意）。
> Studio One のピアノロール上限は G8 = 127 なので全スロットにアクセスできる。

## 3.3 注釈ボキャブラリ

`rules.yaml` で変更可能。以下は既定値。

```yaml
annotation_block: [105, 127]

annotations:
  # ── context（区間指定を想定）─────────────────────
  120: { context: backing_riff }    # 低音リフ。PM 寄り、ダウンピッキング寄り
  121: { context: backing_chord }   # コードバッキング。ストローク寄り
  122: { context: lead }            # 単音リード。レガート/スライド/ベンド寄り
  123: { context: clean }           # クリーン/アルペジオ。サステイン寄り

  # ── 奏法の強制（区間・ピンポイント両用）──────────
  105: { force: sustain }
  106: { force: palm_mute }
  107: { force: brush }
  108: { force: mute_fret }
  109: { force: harmonics_natural } # 自動判定不能
  110: { force: harmonics_pinch }   # 自動判定不能
  111: { force: hammer_pull }
  112: { force: slide_down }
  113: { force: slide_up }
  114: { force: slide_in }
  115: { force: slide_out }
  116: { force: bend_ht }           # 半音
  117: { force: bend_wt }           # 1音
  118: { force: bend_1ht }          # 1音半

  # ── ピッキング方向の強制 ──────────────────────
  125: { stroke: down }
  126: { stroke: up }

  # ── ロック ────────────────────────────────
  127: { lock: true }               # この区間はツールが KS/CC を一切生成しない
```

未使用スロット: 119, 124。将来の拡張用に予約。

## 3.4 優先度チェーン

同一の実音に複数の指示が当たった場合の解決順（上が強い）。

| 優先 | 層 | 与え方 | 粒度 |
|---|---|---|---|
| 1 | **ロック** | 注釈 127 | 区間 |
| 2 | **手動 KS** | 入力 MIDI に既に置かれた KS ノート（11–34 / 91–102） | ノート |
| 3 | **奏法の強制** | 注釈 105–118 | 区間 / ノート |
| 4 | **ストローク強制** | 注釈 125–126 | 区間 / ノート |
| 5 | **context** | 注釈 120–123 | 区間 |
| 6 | 自動ルール | §04 | イベント |
| 7 | 既定値 | `rules.yaml` の `defaults` | 全体 |

同一優先度の注釈が重なった場合は**より短い注釈ノートを優先**する
（区間指定の中の 1 音だけを上書きする、という自然な操作を可能にするため）。
長さが同じ場合は開始 tick が遅いほうを優先し、判定レポートに警告を出す。

## 3.5 往復ワークフロー

出力は type-1 MIDI で、生成 KS/CC は専用トラック `AutoSG_KS` に分離する。

```
out.mid
 ├─ [Guitar]     ← 入力ノート＋注釈ノートをそのまま保持（ツールは書き換えない）
 └─ [AutoSG_KS]  ← 生成された KS / CC（実行のたびにまるごと破棄して再生成）
```

運用ループ:

1. ツール実行 → 雛形が出る
2. DAW で鳴らす。「ここはパームミュートじゃない」と気づく
3. **KS ではなく、元トラックに注釈ノートを描く**
4. 再実行 → `AutoSG_KS` を破棄して再生成。注釈が反映される

修正対象が KS ではなく注釈なので、**注釈レイヤーがそのまま編集インターフェースになる**。
`AutoSG_KS` トラックは毎回作り直すため、署名 velocity のようなヒューリスティックが不要で、
**冪等性が構造的に保証される**。

> トラックをまたぐイベント順序は保証されないため、この方式では
> 全 KS への先行オフセットが必須（§02-2.8）。

## 3.6 最終書き出し

| オプション | 挙動 |
|---|---|
| `--inline` | `AutoSG_KS` の内容を実音トラックにマージし、単一トラックにする（メーカーデモと同形式） |
| `--export` | 注釈ノート（105–127）を除去する |

両者は併用可。DAW 側でトラックをまとめる運用でも問題ないため、`--inline` は任意。

## 3.7 `--suggest`：注釈の初期案生成

context 注釈（120–123）の下書きを自動生成する。

- 2〜4 小節窓 × ヒステリシス付きで `backing_riff / backing_chord / lead / clean` を推定
- 特徴量: 音域中央値・レガート率・ポリフォニー分布・音価分散（§01-1.5 の分析に基づく）
- 結果を**注釈ノートとして元トラックに書き込む**

実行時の暗黙の推定ではなく、ユーザーが目で見て直せる下書きとして出力する点が重要。
外れても害がなく、判断の根拠が MIDI 上に可視化される。
